# Tests and numbers

## Conventions
- Ginkgo v2 + Gomega, package `asm` (internal). Suite + helpers in `asm_test.go`: `mockBuilder`, `TestStateEntity`, `TestEvent`, `createSimpleTestBitmap`, `getTestBitmapByType`, `mask` (int → Bits).
- `TestStateEntity`/`TestEvent` are fake protos (`ProtoReflect` nil): no `anypb`. RPC and cluster specs use `wrapperspb` types (`*wrapperspb.StringValue` entity, `stringValueBuilder`, `clusterBitmap`, `freeAddr` in cluster_test.go).
- Label `cluster` = real raft nodes on localhost (slow). Inside `Eventually` polls use `func(g Gomega)`; a plain `Expect` there fails the spec on intermediate states.

## Harness `testCluster` (cluster_multi_test.go)
- `tc.start(id, joinAddr, bitmap, setup)`, `tc.startClient` (cluster_client_test.go), `tc.node(id)`, `tc.addr(id)`, `tc.leader()`, `tc.opts` (all nodes), `tc.nodeOpts(id)` (per node, eg. certificates), `tc.dataDir` (data dir per id, address kept over restarts).
- `tc.stop(id)` closes the stop channel → node leaves. `tc.crash(id)` stops raft + gRPC only (a crashed follower object may still propose over rpc). `tc.kill(id)` = `requestStop` + wait for closed wal (restart specs). `tc.killAll()` in AfterEach when data dirs are used (Windows can't delete open files). `tc.forget(id)` marks a left/removed node stopped (else `tc.leader()` sees `Lead == 0` from its stopped raft). `tc.stopAll()`.
- Helpers: `expectReady`, `sendWaiting`, `peerIds`, `publishedTransition`, `callLog` (cluster_route_test.go, calls per "node/transition"), `goroutinesIn(function)` (stack dump count).

## Current numbers (2026-10-23, i7-9700K 8 cores, localhost)
- Benchmarks (2026-10-24 evening, quiet machine; ±10-15% run to run): local event ~2.9 µs (~340k/s); start+close serial ~4.2k/s (3 nodes), 128 goroutines ~129k/s (3) / ~104k/s (5); with WAL ~2.2k/s serial, ~88k/s (3) / ~67k/s (5) (B.7, 2026-10-31: serial ~2.9k/s (3) / ~2.7k/s (5), parallel ~87-107k/s (3) / ~64-99k/s (5), noisy); waited forward serial ~6.1k/s, 128 goroutines ~148k/s (3) / ~133k/s (5); session (start, 3 forwards, close) ~30k/s (3) / ~27k/s (5), ~39 KB and ~600 allocs per session; hand-over end to end (start, hand over, close, owner runs it) ~47k/s (3) / ~36k/s (5). Idle container ~2.7 KB, no goroutine.
- 2026-11-12: local event on a node with a read-only transition (`BenchmarkLocalEventReaders`, `StringValue` entity): copy mode 19 allocs, 680 B per event; immutable mode 18 allocs, 616 B, as without read-only transitions (`BenchmarkLocalEvent` 18 allocs, ~660 B). The copy grows with the entity.
- 2026-11-12, A12 (median of 3 fresh runs, same session; before = rounds + rw merged, after = A12): `BenchmarkLocalEvent` ~3.0 µs, 18 allocs, 660 B → ~2.6 µs, 8 allocs, 406 B; `BenchmarkLocalEventReaders` copy 3.4 µs, 19 allocs, 680 B → 2.7 µs, 9, 424 B, immutable 3.1 µs, 18, 616 B → 2.6 µs, 8, 360 B; `BenchmarkRound` (10k containers): empty 264 → 284 ns (3 allocs), one event per container 2.4-2.6 µs, 22 allocs, 1.07 KB → 0.52 µs, 2.0 allocs, 26 B per event (24-26 → 5.2 ms per round), a round batch per container via one deferred event 18-23 → 5.4-5.7 ms (24 → 2 allocs per container), `WithRunAll` without events ~2.1 ms (new; target < 5 ms). Left per delivered event: the `WithTarget` option and a state evaluation.
- Demo, 100k online players, TLS on, trace on: no errors; gateways ~9.3k events/s, ~4.5k forwards/s, 50k containers, ~100k goroutines, ~0.9 GB each; members ~3.9k log entries/s, apply 4-5%; progression ~200 goroutines.
